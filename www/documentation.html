Christie M 4K25 RGB

Controls a Christie M 4K25 RGB over Christie's serial API on TCP port 3002. This projector does not implement PJLink; port 3002 is the only network control interface it offers.

Built for main control board software 1.3.x, developed and verified against a unit running ChristieM 1.3.9. The set of commands the projector answers is a property of its firmware rather than its model — this unit runs Christie's TruLife+ platform, which implements roughly a third of the codes in the published M Series serial API document. On materially different software, some readings may not populate. The projector's running versions are listed on its own web interface, and under Menu → Status → Versions.

Installation

  1. Add the driver to the project.
  2. Set the projector's IP address under Connections → Network. The projector should have a DHCP reservation — the driver has no discovery, and a changed address silently stops all control.
  3. Bind the sources feeding the projector to the HDMI 1–4 video inputs under Connections → Video.
  4. Set the Input N Index properties (see below).
  5. Run the Print Status action and confirm the Lua output window shows the model, serial number and hours. That confirms two-way communication.
Input indices need confirming per installation. The projector does not publish its input list over any interface, so the driver cannot discover it. Each HDMI binding sends a Christie SIN index that you set in the properties. To find the right numbers, switch the projector to an input by hand and run Print Status — it prints the current index and the projector's own name for it, for example 1 One-Port HDMI0.

PropertyNotes
Debug ModePrints all protocol traffic to the Lua output window. Switches itself back off after an hour.
Poll IntervalSeconds between status polls, default 30. Diagnostics (hours, temperature, alarms) are read every tenth poll.
Input 1–4 IndexThe Christie SIN index each HDMI binding selects.

Programming commands

CommandNotes
SetBrightnessLaser power, 30–100%. The projector itself will not run its lasers below 20%, but Christie advise against 30% or lower — at those levels LiteLOC is compromised, lasers may shut down and colours may drop out — so the driver refuses anything under 30%.
ShutterOpen / ShutterCloseThe mechanical shutter (douser).
SetTestPattern21 patterns, as listed in the projector's own menu. Rejected while the projector is in standby.
SetLiteLOCHolds brightness and colour constant over time.
SetLensPositionMove focus, zoom or lens offset to an absolute motor position. The valid range depends on the lens fitted, so the projector rather than the driver decides what is out of range; positions can be negative.
NudgeLensThe same four axes, relative to the current position, for keypad or on-screen adjustment.
SaveLensPreset / RecallLensPresetFour slots holding all four motor positions. See the note below.
SendRawEscape hatch for any code the driver does not wrap, e.g. GAM? to read or SHU 1 to write. Subcodes work too: LAS+POWR?
RefreshStatusForces an immediate poll.

Variables

All read-only, for use in programming: POWER_STATE, BRIGHTNESS, LITELOC, SHUTTER_OPEN, INPUT_NAME, TEST_PATTERN, HOURS, INTAKE_TEMP, ALARMS, CONNECTED, LENS_FOCUS, LENS_ZOOM, LENS_H, LENS_V.

Lens presets are the driver's, not the projector's. This projector has no lens memory — the ILS codes are absent, and recalling a channel does not move the lens. SaveLensPreset therefore stores the four motor positions in the driver's own persistence and RecallLensPreset replays them as absolute moves, which is how a scope / 16:9 screen-ratio preset can work at all here. Presets survive driver and controller restarts, but they are per-driver: replacing the driver loses them, and they are only meaningful for the lens they were saved with.

Lens positions can be read at any time, but the projector refuses to move the lens unless it is on. Both commands check power first and log the reason instead of sending a move that would be rejected. Allow a few seconds for the motors to travel before the variables catch up.

POWER_STATE carries the projector's own wording rather than a boolean — "Standby Mode", "Warming Up", "On", "Cooling Down". Power on takes about 16 seconds, and for the first few of those the projector accepts a TCP connection but answers nothing at all. The driver treats that silence as "unknown" rather than "off", and re-reads the power state 20 seconds after any power command.

Troubleshooting

SymptomCause
No status, CONNECTED is 0Wrong IP, or something else already holds the connection. Confirm with telnet <ip> 3002.
Test pattern command does nothingImage controls are rejected in standby. Turn the projector on first; with Debug Mode on you will see ERR00105 Disabled Control.
Brightness command ignoredValues below 30% are refused, per Christie's own low-brightness guidance; check the Lua output window.
Wrong source selectedThe Input N Index properties do not match this projector's input numbering.
